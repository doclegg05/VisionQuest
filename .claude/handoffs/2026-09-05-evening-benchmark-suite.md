- **What we decided**: the runner evaluates a metric's **floor before** its `exact` rule, so an exact gate metric can fail before any baseline exists (five gate metrics moved from `INFO` to `PASS`-and-failable when this landed); any metric with a numeric floor must declare `direction` explicitly or `bench:validate` rejects it, because `"floor": 0` is a minimum under `higher` and a ceiling under `lower` and the runner defaults to `higher`; a gate or nightly metric may skip its floor only as `"floor": null` plus a non-empty `"reason"`, which makes it an owner-documented `info` metric — a missing `floor` key stays an error, because an omission and a decision must not look alike; `reports/benchmarks/latest/` is written by the nightly commit-back on `main` only, and locally generated result files are untracked; the **initial baseline covers deterministic in-process suites only**, with every timing metric left for CI and the nightly to seed from a machine that will exist again; the browser **collectors run one per Playwright invocation with the e2e seed re-run between them**; advisory-lock SQL lives in exactly one module and is guarded by a test that calls the production functions; a safety-critical gate is not trusted until it has been shown red, and a detector is falsified every run rather than trusted; a sanitizer that normalizes must be measured by a scorer that sees the post-normalization form; suites that read the database use `prismaAdmin` for program-wide rows and `withRlsContext` for staff-scoped reads, never a bare app-client read; the synthetic cohort is verified against a **migrated** database, never `db push`; the readiness consumer mappings were extracted without changing a single number and the disagreement was pinned rather than fixed, because it is a product call.

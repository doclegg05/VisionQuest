- **What we decided** (owner-behalf calls made under the veto-window pattern, all reversible, all named in the PR body): a student's packet strips the résumé's contact block down to a name header when sent to an employer, rather than changing the consent label (SEC-W4); an SMS "still working" retention reply never writes `SpokesEmploymentFollowUp` directly — it advances the Connect pipeline and raises a `connect_retention_confirm` staff alert for a person to record the official DoHS/WIOA checkpoint, because the two records use different clocks (30/60/90 days vs 1/3/6 months) and could otherwise silently overwrite a teacher's verified row; existing SMS opt-ins are not backfilled — a checkbox nobody ticked for the new consent language is not consent, so previously-opted-in students (including the daily coaching text) go quiet until they re-confirm with a phone-verified code; the DoHS export's student identifier column is `Student.studentId`, the same login id `credentials/[slug]` already prints publicly (opens a second instance of F12, tracked in Open Items) rather than inventing a non-authenticating report id ahead of knowing DoHS's real field list; `interested` is a real resting connection state, not a transient one, with legal edges from `sent`/`viewed` straight to `hired` for when an employer skips the interview step; the DoHS export is treated as a program-administration disclosure needing no per-student consent scope, stated in the export module's header for the next reader to check; SMS phone verification (a one-time code) is required before `smsConsentAt` is stamped, so a typo cannot enroll a stranger's number; advisory locks in pooled code are always transaction-scoped (`pg_*_xact_lock`) with distinct class ids, never session-scoped, after the nudge runner's session-level lock was reproduced leaking (one leaked lock, then nine skipped runs in a row).

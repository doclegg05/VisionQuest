# Also 2026-08-20 — log-PII sweep, PR #164 (concurrent session)
- **Date**: 2026-08-20 (worktree `sharp-panini-963729`, branch `claude/sharp-panini-963729` → draft PR #164)
- **What we worked on**: A security audit flagged one line, `recordStudentView`'s failure path logging a student id. Fixing it exposed 38 more sites and a self-contradicting rule: `.claude/skills/student-data-privacy` said "use student IDs, never names/emails" in logs, sanctioning exactly what the audit flagged. Settled the standard in the skill and `.claude/rules/security.md`, then swept every site. Sites now log `studentLogKey(id)` (one-way sha256 prefix) rather than dropping the field, because most of these paths are logged precisely because nothing reached the DB, so the log line is the only trace. Added `redactContactInfo` after finding SMTP and Twilio errors quote the address and number inside the error text, which put back the PII the payload had just removed. The durable artifact is a `no-restricted-syntax` ESLint rule that generated the target list, verified the fix, and now gates in CI.
- **What we decided**: Student ids are PII in logs, same as names and emails (settled a doc contradiction, not a new rule). Correlation keys beat deletion on DB-write-failure paths. No salt on the digest, because cuids are high-entropy and unenumerable. `sms.ts` was fixed alongside `notifications.ts` since fixing only the caller would have been cosmetic. `conversationId` was deliberately kept.

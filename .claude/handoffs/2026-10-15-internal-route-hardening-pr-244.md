# Also 2026-10-15 (internal-route hardening, PR #244)
- **Date**: 2026-10-15 (side session started from the session behind PR #240; branch `fix/internal-route-log-and-secret-compare`)
- **What we worked on**: Two findings from the security audit on #240, fixed test-first. (1) Seven `/api/internal` routes logged `error.message` or `String(err)`, and Prisma messages quote query arguments (alertKeys, `where` clauses) that carry student ids. They now log `errorForLog(error)` (`src/lib/log-error.ts`: name plus Prisma code), and an ESLint block scoped to `src/app/api/internal/**` rejects raw error text inside `logger` calls. (2) `constantTimeEqual` in `src/lib/csrf.ts` returned early on a length mismatch, leaking CRON_SECRET's length; it now compares SHA-256 digests with `timingSafeEqual`. All 13 internal routes also had their own `===` bearer check, which leaks a prefix at a time and is the check an attacker reaches first (GETs skip the proxy's CSRF check, and a script can forge Origin). They now call `isAuthorizedInternalRoute(req)`, and `src/app/api/internal/route-auth.test.ts` fails for any route that doesn't. A security-auditor pass found no critical issues. Its two warnings were the guard missing seven logging forms (closed, with `error-log-guard.test.ts` linting a probe of each) and the two `src/app/api/cron/*` routes still comparing the secret with `===` (left to #240, which moves them).
- **What we decided**: Key Decisions Log rows dated 2026-10-15 (internal-route error logs; shared constant-time route auth).

- **What we decided**: the session verifier rejects any token carrying a `purpose` claim rather than requiring `purpose: "session"`, so the 7-day cookies already in the wild keep working and any future purpose-scoped token is refused by default; a cache write failure degrades to a cache miss, never to an error, and the log line carries no key because keys embed student ids; rate-limit rows are keyed by `<family>:<sha256 prefix>` so a caller can never choose the row size, with the family kept readable so the e2e seed's `startsWith("login:")` still clears both buckets; expired rows are purged opportunistically from inside `rateLimit` (time-gated, fire-and-forget) rather than from a cron route, because the scheduled layer is still dead in prod (F1) and a cron-wired purge would have shipped inert; archive entry names are sanitized at the archive boundary as the authoritative layer with upload-time sanitization as defense in depth, and the character class is Unicode-aware (`\p{L}\p{N}`) because ASCII `\w` would have reduced a Spanish or Japanese résumé name to underscores; the confirm-token expiry prefix must round-trip through `Number` exactly, leaving the token format unchanged so in-flight cards survive their TTL; RBAC reads through `prismaAdmin` with the invariant that every read is actor-independent, and with `ADMIN_DATABASE_URL` unset the no-RLS-extension admin client is uniformly blind, which degrades to static roles rather than a 403 storm; a privilege-tier predicate (`canPerformElevatedStaffAction`) is separate from the scope-breadth one and a test pins that they are not interchangeable.
